## Final validation results

- **Source and test run:** `mvn -B -ntp -Pselenium '-Dselenium.baseUrl=http://localhost:8087' verify` completed `BUILD SUCCESS` on 3 October 2026; 20 appointment/security plus 14 registration backend cases, and five browser journeys all passed with zero failures/errors/skips. See [raw log](evidence/T15_final_maven_verify.txt). Selenium emitted a Chrome CDP version compatibility warning, but no test failed.
- **Live HTTP check:** home and `/physiotherapists` returned HTTP 200; `/actuator/health` returned `UP` on local ports 8082, 8087, and 8089. See the [timestamped JSON](evidence/T15_live_checks.json). This is point-in-time evidence; local services may need starting after reboot.
- **GitHub:** PRs #1–#10 and the `v1.0.0` release are documented. [PR #10](https://github.com/kirti-vispute/physiotherapy-appointment-portal/pull/10) received a [COMMENT self-review](https://github.com/kirti-vispute/physiotherapy-appointment-portal/pull/10#pullrequestreview-5401701041) and merged at `8aadb3679fa9afc8d429dabd3fc02a54cb8588cc`. These single-contributor reviews are not independent peer approval.
- **Jenkins:** the new Poll SCM directive [validated](https://www.jenkins.io/doc/book/pipeline/syntax/) and was [installed with `H/2 * * * *`](evidence/T15_trigger_config.json). Manually started activation build [#10](evidence/T15_activation_build.json) was **ABORTED** by the 20-minute timeout during an unusual backend-test stall; its [console](evidence/T15_activation_console.txt) shows no deployment. The next `develop` push triggered [build #11](evidence/T15_auto_build11.json) with cause **Started by an SCM change**. Its [console](evidence/T15_auto_console.txt) shows 34 backend and five Selenium cases, then Docker Build → Tag → Push → Stop → Run → Health, ending `SUCCESS`. [JUnit](evidence/T15_auto_tests.json) records 39 passes and zero failures/skips. [Deployment metadata](evidence/T15_auto_deployment.json) names tag `1.0.0-b11-58c86345b231`, image digest, container ID, and health `UP`.
- **Independent recovery check:** after a Windows reboot, Docker Desktop reproduced Task 11's transient socket error. The [documented recovery](evidence/T15_docker_recovery.md) moved only transient startup folders to dated backups; Docker data was retained. The existing build #11 container was restarted without replacement. The [4 October live check](evidence/T15_auto_independent_check.json) matched its image and commit labels, verified the registry manifest and volume, confirmed the old build #9 container was absent, and returned health `UP` with home/providers HTTP 200.
